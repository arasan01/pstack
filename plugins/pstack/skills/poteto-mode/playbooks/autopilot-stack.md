### Autopilot-stack

**You own the stack, never the landing. Hand the operator one linear chain of base-chained PRs to review and land.** Autopilot-full's operator gates, native runtime policy, independent verification, durable trails, and audits still apply. Re-read both playbooks from the active source at each audit; this one wins where they differ.

1. **Run Autopilot-full's owner loop with STACK-READY reports.** Each owner has its own worktree and branch. It never rebases onto another branch, including trunk, and never retargets, merges, closes a PR, or arms auto-merge. The root owns topology and the operator owns landing. A dependent item starts from its parent's recorded branch tip, not trunk.
2. **Give topology one writer.** Owners push only their own branches and report head, base, and intended parent. Before a root rewrite or retarget, follow [Merge and restack safety](../references/merge-safety.md): capture the affected chain and remote heads, cancel both auto-merge and queue membership, and verify cancellation. Leave unrelated PRs alone. Pause the owner's branch writes during the operation. Rebase onto the parent's exact tip, publish with `--force-with-lease=refs/heads/<branch>:<captured-remote-head>`, and set the PR base to its parent's branch through the supported native PR tool or resolved forge. Only the root PR targets trunk. Never require `gt`.

   An owner accepts the root's reported push as its new base and lease. If a conflict needs code changes, give that owner the conflicted slice while topology is paused, then have the root publish the result. Do not allow two writers in one worktree.
3. **Reassess drift at the root.** Until landing starts, apply Autopilot-full step 5's context test to each link, using its parent as its base, and rebase bottom-up only where needed. Record the verdict's head SHA, base SHA, base branch, and stable base-to-head patch-id. Apply the shipping patch-id rule link by link, re-running CI and mergeability after each rewritten push and independent review wherever evidence no longer applies. Nothing enters the delivered chain without Autopilot-full step 4's clean verdict.
4. **Deliver the chain, then stop writing to it.** Every link carries its verdict and evidence in its PR or a linked artifact. The operator reviews and lands it. Once landing starts, only the coordinated next-child preparation in `playbooks/shipping.md` may change a branch or base. A mid-landing problem goes through the root to the operator; any fix waits for the operator's go.

**Choosing between the autopilots.** Use Autopilot-full for independent PRs and Autopilot-stack for sequenced or coupled work that needs one reviewable chain. Neither grants merge authority or overrides the operator's merge gate.
