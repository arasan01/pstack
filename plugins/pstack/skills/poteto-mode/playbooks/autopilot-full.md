### Autopilot-full

Resolve the driver skill through [poteto-mode's Non-negotiables](../SKILL.md#non-negotiables).

**You own the verdicts, never the PRs. One owner carries each PR to merge-ready. The operator reviews and merges; a clean independent verdict never substitutes for that authority.**

A verdict covers a patch and context; green CI covers a head. Run the full swarm once, and again for a major change. Later minor fixes still need an independent verifier. The patch-id rule in `playbooks/shipping.md` can preserve a lane's result, but every new head needs current checks and mergeability.

On omp, [the native mapping](../references/omp-tools.md) wins over generic dispatch, model, effort, lifecycle, permissions, concurrency, and scheduling guidance. pstack supplies a workflow, not a replacement runtime.

1. **Honor the operator's gates.** A request to state the plan is not a go. On explicit go, record the full objective, queue, owner count, verification lanes, merge authority, and two-fix-forward ceiling in durable standing orders and the native task list. State the program's size before dispatch. More than three owners needs the operator's go on that size unless the request already named it. Keep operator-owned and out-of-queue items excluded. A stop or hold immediately suspends writes.
2. **Give each PR one isolated owner and a durable trail.** Resolve the forge once. Default to `gh`; prefer `origin pr` only when the installed Origin resolves the repository, and record any fallback. Never require `gt`. Each owner gets its own worktree and branch, opens a ready PR early per `playbooks/opening-a-pr.md`, proves the real artifact, triages review bots per `../references/bugbot-triage.md`, and babysits to green per `playbooks/babysit.md`. It stops at merge-ready and never merges or arms auto-merge.

   Finish `/deslop` and `/no-comments`, prepare current trunk, and report the code-ready head before self-proof so the first swarm sees finished code. Report every later head. Fix rounds keep that base unless trunk conflicts or breaks CI. Run the project's required checks for touched paths on the committed head before a push that starts verification; a hook pass alone is not proof.

   Assume the execution environment can disappear. Soon after starting, publish an authorized branch snapshot and start `decisions.tsv` in the agreed durable agent store per **show-me-your-work**. Push after each verifiable unit when authorized. Record each child's ID, state, and stuck-after runtime from comparable past runs in `children.tsv`. Use a project-specific durable store, not a session scratchpad or an assumed global path. Force-push only the owner's branch with an explicit lease pinned to the remote SHA captured before rewriting. Stop and reconcile an unexpected push rather than refreshing the lease to overwrite it.
3. **Run independent owners in parallel off trunk.** Isolate writers first and obey native concurrency and delegation limits. Dependent work uses Autopilot-stack or waits for its parent to merge. Resolve model, effort, and supported speed through native policy and the mapping, not a pstack dispatch wrapper.
4. **Swarm-verify once, then verify each change.** At the code-ready SHA, use independent verifiers per **swarm**. Re-run the gates, exercise load-bearing behavior through the project's matching driver, and run at least two focused correctness-audit lanes that distrust the PR body. Compare the same scenario on trunk and head. If trunk lacks the feature, record that and verify the added behavior plus the end state the user waits for. Save evidence appropriate to the target: UI captures, native-device output, terminal transcripts, request and side-effect records, or public-API consumer results. No clean verdict without real-artifact evidence and the root's audit of the receipts.

   Another full swarm is for new behavior, a redesign, or a large new diff. A rebase, conflict resolution, or minor fix gets an independent verifier at the new head, with current gates, the relevant behavioral probes, and correctness review of the changed diff. Preserve older results only under the shipping patch-id and context rule. The author, CI, and review bots do not count as independent review; if no reviewer can run, keep the gate closed.

   Send proven PR-caused findings to the owner in one fix-forward, including defects labeled as notes. Ask for a behavioral regression test across affected sites, or a reproduction receipt where no useful test can show it. A pre-existing trunk defect does not gate this PR unless the PR copies or newly exposes it. Record it separately. After two failed fix-forwards, report the PR blocked with evidence and wait for the operator's ruling on that PR. Never push a fix into another owner's branch.
5. **Hand off only the verified patch in its tested context.** Merge prep starts after verification lanes start, prepares current trunk, reports the resulting head, and waits for green CI. Before handoff, fetch trunk and assess whether new changes affect the patch. Rebase for conflicts, overlapping source changes, or changes to required checks. For caller or dependency drift, run the patch's checks against an isolated merge result. A shared lockfile change needs no rebase only if a frozen install passes on that result and the changed packages resolve as they did on the head. A failed install requires repair.

   Apply `playbooks/shipping.md`'s patch-id rule to any rewrite, base change, or preserved lane. An unchanged patch does not establish applicability to new dependencies or context. If trunk would force a third rebase past merge prep, have the root sequence the colliding work. Present the exact merge-ready head, base, verdict, CI, and receipts to the operator, then stop. No owner merges. Any later landing follows the operator's authority and [Merge and restack safety](../references/merge-safety.md).
6. **Audit the program and guard its checks.** Loosening a budget, gate, or allowlist needs verifier proof and a fresh root countersign within the operator's approval grant. Record that countersign for a lane to check. Remove disabled or soft-failed checks introduced to evade a gate. Never give or bypass a forge-enforced approval.

   Schedule hourly audits only through a scheduler the runtime actually exposes. Otherwise retain an actual watcher through native background-process tools and act on delivered output; report when recurring agent wakeups are unavailable. A shell timer is not an agent wakeup. Re-read this playbook and the standing objective at each audit. Inspect owner and child records and judge progress by commits, pushes, check changes, or trail rows, not status prose. Fix unreported state through its owner. An agent awaiting an operator or parent answer is not stuck. When a lane stalls or cannot start, revoke its write ownership and confirm it stopped before reusing its branch or worktree. If stopping is unavailable, isolate its replacement on new output paths and reconcile before integration. Catch the operator up through **ketchup** only when something changed; keep unchanged ticks quiet and log them. Continue until delegated work is reconciled, including post-merge checks.
7. **Honor a hold immediately.** Send every owner a zero-writes order, collect its state, and preserve its brief until the operator releases it.

**Reply:** catch the operator up per **ketchup**, covering each PR's state and verdict, confirmed landings, countersigns and reasons, open operator gates, and links to PRs and durable trails.
