### Session pickup

**You own the resume point. Read the prior trail, don't redo it.**

1. Read the project checkpoint first using [Resume storage](../references/resume-storage.md). It locates the note and artifacts without a prior-session path. A missing pointer permits fallback to this workspace's runtime transcript store, an available cloud-agent URL, or a pushed branch. An unavailable or incomplete checkpoint needs diagnosis, not silent fallback. Follow the runtime mapping, including omp's active-profile sessions, and never scan unrelated workspaces. Read metadata and recent messages first, then decision points. Delegate bulk parsing only under native policy; resolve model, effort, and supported speed through the mapping and Subagents section.
2. Reconstruct the branch, worktree, landed changes, pending work, and decisions from the trail and repository state. For human rulings, follow [Claims about human decisions](../../why/references/epistemics.md#claims-about-human-decisions). An agent summary is not the original ruling.
3. Compare shipped work with the plan and name the resume point. Do not repeat completed reproduction or investigation. Recheck inherited claims that affect remaining work and read linked artifacts, including requested questions or checklists.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here. The routed playbook owns the rest.
5. Verify the inherited claims against the original goal on the real artifact (the **principle-prove-it-works** skill). A passing prior self-report is not the proof.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome.
