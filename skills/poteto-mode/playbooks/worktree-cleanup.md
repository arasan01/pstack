### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `node skills/poteto-mode/scripts/worktree-audit.mjs <repo-path> <transcripts-path> ...` (principle-build-the-lever). Pass only authorized session roots for this repository and its worktrees; the default searches runtime-wide transcript roots. The port has no `-b` option. Its `MERGED` column uses the discovered default branch, so establish ancestry to the intended target separately when a PR targets another branch. It reads worktree paths from `git worktree list`, not hand-typed guesses, and classifies size, age, merge state, uncommitted work, PR state, locks, and recent chat usage. Background a slow scan through the native process tools. Unknown or incomplete audit facts never authorize deletion.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or your own session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row or uncertain candidate, inspect the relevant transcripts, using read-only investigators for bulk work when native policy permits. Report pinned or ongoing chats and every worktree their children use. A pinned chat can own sibling arena or reproduction trees even when those names never appear in the session list.
4. Pause on irreversible loss. `wip:N` counts tracked changed paths; `untracked:N` counts files git has never seen. Both can appear together. List them with `git -C <path> status --porcelain --untracked-files=all --ignore-submodules=none`, show `git -C <path> diff HEAD --ignore-submodules=none --submodule=log`, and get a decision before deleting either kind. An empty diff omits untracked files and may conceal submodule work. Inspect status inside each changed submodule too. `hold-locked` records another tool's lock and reason in `LOCKED`; never unlock it or bypass a refused removal with `rm -rf`. Only clean, merged, unlocked, not-in-use worktrees proceed within the user's cleanup authority.
5. Prune the confirmed set. Remove each approved worktree with `git worktree remove <path>`, using `--force` only for work the operator explicitly approved discarding. If a directory survives, diagnose the refusal before considering any filesystem deletion. Never bypass a lock, usage hold, unknown state, or unapproved uncommitted work. Prune stale metadata with `git worktree prune`, then re-list and record `df -h /`. Branch refs preserve ordinary commits; commits inside a submodule can disappear with its worktree, so preserve them before removal.
6. Reclaim other state only within the requested scope. On Apple platforms, inspect simulators and runtimes before deleting unused testing clones or unavailable devices. For caches, list the exact directories and respect retention requirements. Session history is not a disposable cache: preserve pinned, recent, and checkpoint-linked transcripts that **recall** and Session pickup need. Do not erase runtime-wide history or user settings as incidental cleanup.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
