### Investigation

**You own the answer. Plan, route, write.**

Investigation requests are read-only. They produce a cited explanation or a recommendation, not a code change.

1. Trace the code the question concerns. Use `skill:how` to explain the current flow or ownership, and `skill:why` for motivation or history.
2. Throughput checkpoint stays one line: `throughput checkpoint: n/a, read-only investigation`.
3. Cite the sources that establish the answer. Explain the concepts, flow, code locations, and caveats that matter. For a choice between alternatives, give a recommendation and a tradeoffs table.
4. Apply the **unslop** skill to the reply.

No PR, babysit, implementation, or proposed design review. If the investigation leads to an authorized change, route that work to Bug fix or Feature with the evidence you already have.

**Reply:** the investigation output. For "are we sure?" answers, include your real judgment with reasons. Push back if the premise is wrong (see Autonomy).
